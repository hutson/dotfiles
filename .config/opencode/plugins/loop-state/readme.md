# loop-state

Appends a state diagram of the engineering loop to the session sidebar: phases 0 through 8 as a vertical chain (the grade gate chain nested under `7 grade`), each phase line naming the agent that does that work (the `7 grade` line shows the round counter instead, and its gate lines name the graders), plus a mark: `✓` done, `▶` current, `●` running (a worker attributed to that line has an active session; `●x2` means two running workers on one line), and `PASS` or `↺n` gate marks taken from the newest completed `Round <n>:` line in the goal file's `## Status` section, where `↺n` means that gate failed and the loop returned to node `n` (a `test-immutability` tripwire re-routes the quality-assurance mark to `5` instead of `6`). A running worker's `●` replaces that gate's stale mark. A legend and two short notes define the marks, what a round is, and when `test-design` re-runs.

The current phase comes from the goal file's `- State:` field (see `skills/loop/references/goal-file.md` for the vocabulary), resolved by the same ranking rule as `/resume`: this project's newest ranking `Updated:` stamp wins, and a tie among ranked candidates shows an ambiguity note instead of guessing (a lone candidate is shown even when its stamp does not rank, because a passive widget has nothing to ask). Agent-written strings are never rendered raw: a `State:` value outside the id charset shows as `state: <invalid>`, files whose slug violates the documented `^[A-Za-z0-9_-]+$` contract are skipped, and an unrecognized `session.status()` shape counts as not running, so live `●` badges fail closed rather than wrong. Live badges come from the viewed session's family status, so a worker that is dispatched but whose phase transition is not yet written still shows, and any running agent outside the vocabulary (for example `explore`) badges the current line. The widget hides itself when the project has no goal file.

The sidebar stays opt-in: `session.sidebar` remains `hide` in `cli.json`, and you show the diagram yourself with `session.sidebar.toggle` (default `<leader>b`, so `ctrl+x` then `b`) to passively observe a running loop. Keeping the node vocabulary in sync is deliberate: a phase change needs matching edits in `skills/loop/SKILL.md`, its `references/goal-file.md`, and this plugin's node table.
