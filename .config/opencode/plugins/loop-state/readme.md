# loop-state

Appends a state diagram of the engineering loop to the session sidebar of loop sessions: phases 0 through 8 as a vertical chain (the grade gate chain nested under `7 grade`), each phase line naming the agent that does that work (the `7 grade` line shows the round counter instead, and its gate lines name the graders), plus a mark: `✓` done, `▶` current, `●` running (a worker attributed to that line has an active session; `●x2` means two running workers on one line), and `PASS` or `↺n` gate marks taken from the newest completed `Round <n>:` line in the goal file's `## Status` section, where `↺n` means that gate failed and the loop returned to node `n` (a `test-immutability` tripwire re-routes the quality-assurance mark to `5` instead of `6`). A running worker's `●` replaces that gate's stale mark. A legend and two short notes define the marks, what a round is, and when `test-design` re-runs.

The current phase comes from the goal file's `- State:` field (see `skills/loop/references/goal-file.md` for the vocabulary). The goal file is found by link, not by name: the supervisor records its own session id (from `printenv OPENCODE_SESSION_ID`) in the file's `- Session:` field at creation and updates it whenever `/resume` continues the loop in a new session, and the widget shows a file when that id names the viewed session or a member of its family, ranked by `/resume`'s rule among the family's linked files (the strictly newest ranking `Updated:` stamp wins; a tie shows an ambiguity note instead of guessing; a lone candidate is shown even when its stamp does not rank, because a passive widget has nothing to ask). Name-prefix lookup is gone by design: a loop started at an umbrella directory (several sibling repositories under one working directory) names its goal file after the deliverable rather than the root, and prefix matching silently showed nothing for it (the 2026-11-06 pinbump bootstrap loop, invisible in the sidebar at `/var/home/hutson/workspace`). Nothing renders unless the viewed session's family contains a `supervisor` session: `/loop`, `/resume`, and `/save` all select that agent and dispatched workers share its family, so outside a loop there is neither diagram nor warning. Inside a loop whose family no goal file links, the widget shows a short `loop: no goal file` line rather than hiding silently, because the silent absence was the original failure. Agent-written strings are never rendered raw: a `State:` value outside the id charset shows as `state: <invalid>`, file names violating the documented `^[A-Za-z0-9_-]+$` contract are skipped, a `- Session:` value outside `^ses_[A-Za-z0-9]{1,64}$` links nothing, and an unrecognized `session.status()` shape counts as not running, so live `●` badges fail closed rather than wrong; if the family API itself fails, the set holds only the viewed session, so the gate and link fail closed (nothing shows) rather than matching another loop. Live badges come from the viewed session's family status, so a worker that is dispatched but whose phase transition is not yet written still shows, and any running agent outside the vocabulary (for example `explore`) badges the current line.

The sidebar stays hidden at rest: `session.sidebar` remains `hide` in `cli.json`, but the first sighting of a loop in a TUI flips it open, once per session family per process (`/loop` is when the human starts watching). `session.sidebar.toggle` (default `<leader>b`, so `ctrl+x` then `b`) still works by hand in both directions. Where the keymap exposes the toggle's command state, the reveal skips an already-open sidebar; an unreadable state accepts one stray flip per loop, because hiding is the configured default and reopening is one keystroke. Keeping the vocabulary and the link in sync is deliberate: a phase change needs matching edits in `skills/loop/SKILL.md`, its `references/goal-file.md`, and this plugin's node table, and the `- Session:` link spans `goal-file.md` (the field), `SKILL.md` (the recording rule), `agents/supervisor.md` (the exact `printenv OPENCODE_SESSION_ID` shell form), and this plugin's `sessionIdPattern`.
